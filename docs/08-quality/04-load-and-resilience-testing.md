# Load Testing and Failure Injection

Targets derive from A-01 (to be replaced by OQ-05 answers).

## 1. Load profiles

| Profile | Description | Target | Pass criteria |
|---|---|---|---|
| L1 Arrival wave | OTP request+verify+name+lobby for new participants | 50 OTP flows/s for 10 min | p95 < 500 ms (excluding SMS provider), 0 errors except 429 by design |
| L2 Gameplay steady | create→start→result (valid synthetic logs) mixed games | 100 results/s for 20 min | p95 result < 400 ms, p99 < 1 s; 0 lost results; DB CPU < 70 % |
| L3 Leaderboard viewers | 2 500 concurrent SSE leaderboard viewers + 100 fetch/s | 30 min | hint latency p95 < 2 s; memory stable |
| L4 Admin/display | 30 admin + 10 display streams during L2 | 4 h soak | no memory growth > 10 %; no reconnect storms |
| L5 Reward contention | all results hit same limited reward rule | 100 results/s | exact inventory, no deadlocks, p95 < 600 ms |
| L6 Draw at scale | 50k eligible participants, 100 winners, during L2 | — | execution < 5 s; reproducible |
| L7 Outbox backlog drain | 50k pending deliveries with fake Snowa at 50 req/s | — | drains without affecting L2 latency |
| L8 Static burst | 1 000 cold app-shell loads/min | — | proxy CPU/bandwidth within budget |

Synthetic results are generated by game-core bots so they pass validation (exercises the replay path realistically).

## 2. Failure injection scenarios

| # | Inject | Expected behavior |
|---|---|---|
| F1 | OTP provider timeout/500 | `503 OTP_PROVIDER_UNAVAILABLE`, Persian retry; alert; logged-in users unaffected |
| F2 | Snowa API down 1 h | Results accepted; backlog grows; admin degraded badge; drains after recovery; no duplicates if idempotency supported |
| F3 | Kill API replica during L2 | Clients retry; no duplicate attempts/tickets; SSE clients reconnect to other replica |
| F4 | Kill worker mid-delivery | Leases expire; deliveries resumed |
| F5 | Restart PostgreSQL (failover) | 503s during outage; pending results resubmitted within late window; no data loss for committed tx |
| F6 | 2 s added latency / 5 % packet loss on client network | Gameplay unaffected; submissions retried; UI shows sending state |
| F7 | Client offline for whole game | Result submitted when back (within late window) with `LATE_SUBMISSION` flag if past deadline |
| F8 | Double-click draw execute (scripted parallel) | One draw completed |
| F9 | Display disconnect during reveal | Reconnect shows correct revealed winners |
| F10 | Reward inventory exhausted mid-burst | No overspend; results still accepted; admin alert |
| F11 | Clock skew on API hosts (+5 min) | No effect (DB time authoritative) |
| F12 | Stale service worker after deploy | New build detected; config/API unaffected; old game chunk rejected with `426` if incompatible → reload prompt |
| F13 | SSE blocked by proxy | Clients fall back to polling |
